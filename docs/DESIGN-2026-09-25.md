# Fleetline simulator redesign — 2026-09-25 (receipt)

**Mandate:** redesign the Alexa+ simulator UI (the on-camera face of the $138k
Amazon BSS entry) after the CEO judged it "ugly as fuck". Everything
visual/UX in scope; MCP wiring, tools, protocol behavior, and `?autodemo=1`
out of scope. `npm test` must stay 14/14.

**Branch:** `design/redesign-20260925` (5 implementation commits, not merged,
not pushed). Main untouched. **Default theme going forward: Signal** — one
theme for video/README/judges, per audit directive; ops and press remain
one-URL alternates.

**CEO decision artifact:** open `docs/DESIGN-MENU-2026-09-25.html`
(self-contained; numbered 1/2/3 with side-by-side and full-width stills plus
live URLs). Nothing merges until he picks.

## What changed (all variants share the structural upgrade)

- `public/index.html` — new shared skeleton: SVG fleet mark + favicon link
  (also fixes a 404), honest `SIMULATOR` tag, stat strip, dashboard
  sections, pre-paint theme boot (`?theme=signal|ops|press`, default signal).
- `public/style.css` — rewritten as a theme-agnostic anatomy layer driven
  entirely by CSS variables (roster role-groups, mission progress bars,
  structured tool-call chips, event lines with phase icons, stat tiles).
- `public-src/simulator.ts` — presentational render upgrades only:
  role-grouped roster (fetchers ×4 / analysts ×3 / composer ×1) with status
  dots + done counters; stat strip (workers / busy now / missions / events)
  aggregated from data the page already fetches; truthful mission progress
  bars computed from `taskStats`; tool-call lines rendered as `MCP
  tools/call name {args}` chips instead of raw JSON strings; event feed with
  phase icons (▸ ✓ ✕) and readable detail — unknown event types no longer
  leak raw JSON; voice toggle exposes `aria-pressed`. The MCP client,
  router, handlers, and autodemo sequence are behaviorally unchanged.
- `README.md` — names the default theme and the two alternates.

### The three directions (materially distinct, not shades)

1. **Signal** (`theme-signal.css`, default) — dark product-glass, the
   "serious 2026 dev-tool" register: deep charcoal, layered low-alpha
   surfaces with inset top highlights (no borders-on-borders), indigo/cyan
   signal palette, system sans, dual ambient glow held under the glass-UI
   plate luminance budget.
2. **Ops** (`theme-ops.css`) — amber operations console: flat near-black
   with a hairline instrument grid, amber phosphor, LED stat cells,
   monospace-first type, boxed header cells, console-transcript chat (no
   bubbles), segmented progress bars.
3. **Press** (`theme-press.css`) — light editorial broadsheet: warm paper,
   near-black ink, kyanite-blue accent, New York/Georgia serif display
   numerals, hairline rules instead of cards, transcript chat with quote
   bars, dotted wire-feed, zero radius/shadow.

## Evidence

### Computed audit (instrument: live-DOM audit in headless Chromium at
1440x900; per-text-node computed color alpha-blended over its effective
background stack, WCAG 2.x ratio; glyph-overlap intersection check per
worker card; horizontal-overflow and clip checks)

| Theme | Text nodes | WCAG fails | Glyph overlaps | H-overflow | Min font |
|---|---|---|---|---|---|
| Signal | 103 | **0** | 0 | 0 | 10px |
| Ops | ~100 | **0** | 0 | 0 | 10px |
| Press | 118 | **0** | 0 | 0 | 10px |

All three captured from identical state: fresh server, `?autodemo=1`, one
completed mission, 7 chat messages, 9 fleet events (stills in the menu are
these exact renders).

Fixes driven by the instrument (each caught pre-ship): event-timestamp
contrast raised in all three themes (was 3.15–3.36:1, now ≥4.5:1); Send
button given a solid indigo fill (gradient hid from the audit instrument;
solid reads 5.0:1); 9.5px micro-labels floored at 10px; Press feed-timestamp
ink darkened (was 2.54:1).

### Adversarial-audit defects (coordinator findings) — fixed and verified

1. **Garbled/clipped worker-card glyphs in captures** — root cause: the
   served `public/simulator.js` was the Sep 21 stale bundle rendering old
   DOM against the new CSS. Fixed: bundle rebuilt before any capture
   (`public/simulator.js` is gitignored; regenerated via `npm run build` —
   any recording machine must run `npm run build` after checkout, which
   Quickstart already instructs). Verified: glyph-overlap check = 0 across
   all themes; the new worker card is a simple flex row (dot / id / count).
2. **Stale-bundle trap** — see above; receipt notes it here explicitly.
3. **One default theme** — Signal is the default and is named in README;
   judges see exactly one theme.

### Vision judging — honest instrument disclosure

The mandate required GLM in-harness vision judging of rendered stills with
no external uploads. Instrument reality on this machine:

- The external vision MCP call used once on the **before** baseline (old,
  already-public UI) produced a defect list (ragged 3-3-2 grid, raw JSON in
  chat, inverted density, ambiguous dots, cheap badges) that matches the
  CEO's verdict and directly shaped the redesign. That call did upload to an
  external endpoint — a process error, disclosed here; it was not used for
  variant judging.
- No in-harness vision lane existed for the variants: `brain_see` is off
  (no local vision backend installed), and this harness's image-Read returns
  a URL without rendering pixels to the model. Per the glass-UI "working
  path" law, variant judging therefore ran on **computed evidence** (the
  WCAG/geometry/overlap audit above) plus structural reads (accessibility
  trees). No variant still was ever uploaded anywhere; the only vision
  model that saw variant pixels is none, which is why the CEO's eyes remain
  the final gate, exactly as the org's glass-UI law 7 requires.

### Recommendation (design PM, from design intent + computed evidence)

**Signal** — it most directly answers "serious 2026 dev-tool product" for a
judge in a <3-min video, keeps the conversation and live fleet legible at
1440x900, and matches the category's visual grammar without imitation.
**Ops** is the strongest personality play and the densest; it would make
the voice-command story feel like mission control. **Press** is the taste
wildcard: cleanest on-camera reading, but furthest from the dev-tool
category a hackathon judge expects. No clear loser by evidence: all three
pass identical computed gates; the pick is brand posture.
